## Acceptance criteria
Each one must be checkable in `verify.md`.
1. [ ] **S2.1 Terms first.** For every source added in step 2, a line in `evidence/` records the page read, what it says about automated reading and reuse, and the robots.txt of the endpoint, dated, before the source is created. A terms page that cannot be read is said so, and the source stays off until the owner has read it.
2. [ ] **S2.2 BCG.** A `phenom` source (`host careers.bcg.com`, `site global/en`, `countries ["France"]`, company BCG) is seeded switched off; a test reads saved copies of real responses; a live read returns its France jobs (count recorded); it is rehearsed on a Postgres copy (S2.7).
3. [ ] **S2.3 No duplicates.** Before any consulting employer is added, it is checked against the sources already in the database (by name and by configuration), the way Amundi was found in step 1. An employer already covered under another name (for example Capgemini Invent, whose jobs come through the Capgemini source) gets the verdict "already covered" and no new source.
4. [ ] **S2.4 A verdict for each of the 25.** Each ends in `evidence/consulting_verdicts_<date>.md` with one of: a source added (S2.1 and S2.6 apply), already covered (S2.3), or a row in `unsupported_employers.csv` (status, blocker, how to reach their jobs anyway, date). The count of each is recorded. B employers are done before C.
5. [ ] **S2.5 Tests.** Every new adapter or adapter change has tests on saved real responses (no live calls in the suite), and the full suite passes with `DATABASE_URL=` on SQLite, with 0 new failures. A new adapter is built only if one hiring system serves three or more of the employers (or BCG needs it, which it does not); anything else goes to `unsupported_employers.csv` as `needs_adapter`.
6. [ ] **S2.6 Reproducible and safe.** New sources are added to `seed_employers.py`, all switched off; the hosted script (`seed_hosted_sources.ps1`) gets a `-Step` choice so step 2's names can be dry-run and written separately from step 1's; before the owner's write, a dry run on a fresh scratch copy shows only the new names would be created and no existing source changes (checksum, as in step 1).
7. [ ] **S2.7 Neon reads and relevance measured.** The new sources are run through the real runner on a fresh scratch copy of the latest dump, with the request count stated first and the owner's go; evidence gives requests, bytes sent per source (first pass and steady state), and, per source, the jobs stored and how many are in the owner's cities. The owner accepts the figure and says which sources to enable.
8. [ ] **S2.8 The lists match.** The consulting rows of `data/employer_coverage*.csv` and `unsupported_employers.csv` are updated to the verdicts once the sources exist on the hosted database; final counts (covered, unknown, unsupported) are recorded next to the 2026-11-03 baseline (13 consulting-like covered, 29 unknown). The `data/` files are gitignored: the counts go to `evidence/`.
9. [ ] **S2.9 The weekly measure.** One week after the first full run with the consulting sources on, the number of consulting jobs in the owner's cities that are new to the catalogue is recorded, with the share of all new jobs that week (the owner needs this every week). If it can only be read after the verify stage, `learn.md` carries it, dated.

## Design in brief
- **The step 1 method, unchanged:** discovery of the hiring system from the employer's own careers page (`jobs/careers.py`, with the Workday-link fix of step 1), a scan of the page for any known system, a live read with the app's own adapter and no database, robots.txt and terms, then a seed entry, a test and a Postgres rehearsal.
- **Leads, not facts** (from a web search or from memory, to verify, never to trust): Sopra Steria appears on SmartRecruiters under `SopraSteria1`; EY's careers site looks like a TalentBrew site (the `sitemapjobs` adapter reads those); Deloitte, KPMG, PwC and the strategy firms (McKinsey, Bain, Kearney) have their own sites or Workday tenants. BCG is the only one verified (Phenom).
- **BCG first** (cheapest, and the owner's example), then B, then C in two batches. Phenom, Workday, SmartRecruiters, Greenhouse, Lever and TalentBrew sites need no new adapter.
- **Rejected:** one big "all consulting" source (no such thing); building adapters for single employers (out of scope unless three or more share a system); enabling by default (new sources stay off until the owner has seen their city counts).

## Interfaces and data
- Changed: `jobs/management/commands/seed_employers.py` (entries, all off), `scripts/seed_hosted_sources.ps1` (`-Step`), `docs/unsupported_employers.csv/.md`, tests. New evidence files in this cycle's `evidence/`.
- Written outside the repo: the hosted `jobs_source` table, by the owner (a second script run after the Neon snapshot); the `data/` lists.

## Constraints
- Same as step 1: robots.txt obeyed, no anti-bot workaround, a polite rate, secrets never printed, the hosted database written only by the owner.
- **Real-site reads:** discovery and live reads are about 10 requests per employer (about 250 in all for the 25) plus the measurement run; I state each batch's count before running it, and ask before anything much larger.
- Neon: each source's cost is measured and accepted before it is enabled (S2.7).

## Out of scope
- Employers that are not consulting (the other priority B and C rows), VC boards, aggregators and alert e-mails (cycle 018).
- New adapters for single employers.
- The product-level legal review of sources (PRD.md §2).

## Rollback
- Repo changes: git, nothing is committed until the owner agrees. Scratch copies: `measure_reads.ps1 -Clean`.
- Hosted: new sources are created switched off and can be disabled or deleted by name; the snapshot taken before the write is the way back.

## Risks
- Several firms will have no readable public feed (big networks often use closed or script-loaded sites): the likely outcome for some of the 25 is `unsupported_employers.csv`, which is a valid verdict.
- A firm's jobs may be on one shared global careers site with thousands of jobs: the source then needs a country filter (as Phenom's `countries` and Workday's `search_text`) or it stores worldwide jobs for nothing; S2.7 measures it.
- More sources add Neon reads (cycle 001): measured, accepted, and switched on in batches.
- The 29 Oct dump is old by now: slice 14 uses the newest dump and the owner's dry-run listing, and slice 19's dry run compares names again.
